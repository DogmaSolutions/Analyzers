# DSA050

Testing a flag and then changing it is not atomic.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA050                                                                                        |
| Title        | Testing a flag and then changing it is not atomic                                             |
| Category     | Code Smell                                                                                    |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ❌                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

*"Only start it once"*, *"only flush when something is pending"*, *"only go from Idle to Running"*: the natural way to write these rules is a flag, a test, and a change.

```csharp
public void Start()
{
    if (!_started)          // 1. test   (DSA050)
    {                       //    <-- another thread can run here
        _started = true;    // 2. change
        StartWorker();
    }
}
```

The test and the change are two operations, and the race lives **between** them:

| Time | Thread A | Thread B | `_started` |
|:-----|:---------|:---------|:-----------|
| 1 | `!_started` → `true`, enters | | `false` |
| 2 | | `!_started` → `true`, enters | `false` |
| 3 | `_started = true` | | `true` |
| 4 | `StartWorker()` | `_started = true`, `StartWorker()` | `true` |

The "only once" code ran twice. `volatile` does not help: it makes each single read and write visible to the other threads, it does not make the **pair** atomic (see [DSA046](DSA046.md) for the same lesson on `++`).

## ✅ What is reported

An `if` whose condition tests a single field of the class, and whose branch changes the field to another **constant**, when the code is not inside a `lock`:

| Scenario | Shape | What goes wrong |
|:---------|:------|:----------------|
| **Set once** | `if (!flag) { flag = true; ... }`, `if (flag == false)`, `if (flag) {...} else { flag = true; }` | The "only once" code runs more than once |
| **Consume** | `if (flag) { flag = false; ... }`, `if (flag == true)` | The work (or the signal) is handled twice, and a set made between the test and the clear is lost |
| **State transition** | `if (state == Idle) { state = Running; }`, `if (Idle == state)`, `if (state != Idle) {...} else { state = Running; }` (an `enum` or an integer) | Two threads make the same transition |

The field is a `bool`, an `enum` or an integer (`int`, `long`, `short`, `byte`, `uint`, `ushort`), not `readonly`. The diagnostic is located on the `if (...)` header, and the message names the field, the value it is set to and the value that was seen. For a `volatile` field it adds a note that the keyword does not help.

A private member is reported when the field is also used by another member (a constructor or an initializer does not count), or is `static` or `volatile`; a member that is not private can be called by any thread, and is always reported (`require_shared_access`).

## 🚫 What is *not* reported

| Case | Why |
|:-----|:----|
| The code inside a `lock` (default, `skip_inside_lock`) | The test and the change are protected, as long as every access takes the lock: see [DSA049](DSA049.md). A lambda inside the lock is not exempted, it can run later |
| A constructor (default, `skip_constructors`) | Nobody else can see the instance yet |
| The same value (`if (flag) { flag = true; }`), a value that is not a constant, a compound assignment (`n += 1`), an assignment in a lambda or a local function of the branch, the field of another object | Not a change of the tested state |
| `x != K` in the *then* branch, `x == K` in the *else* branch (for non-boolean states) | The condition does not say what the field holds there |
| Null checks on references (`if (_x == null) { _x = new X(); }`) | Lazy initialization: see [DSA007](DSA007.md) |
| Properties, locals, fields of other objects, `string`/`double` states | Not a field of the class that the rule can follow |
| Generated files | `*.Designer.cs`, `*.g.cs`... are ignored |

## 🔧 Alternatives

| You want | Use |
|:---------|:----|
| Something to happen **once** | `Lazy<T>`, `LazyInitializer.EnsureInitialized`, a static constructor, or `Interlocked.CompareExchange(ref _started, 1, 0) == 0` on an `int` |
| A signal to be **consumed** by one thread | `Interlocked.Exchange(ref _pending, 0) == 1` on an `int`, or `SemaphoreSlim` / `ManualResetEventSlim` / `Channel<T>` |
| A **state machine** | `Interlocked.CompareExchange(ref _state, Running, Idle) == Idle` on an `int` state, or a `lock` around the whole transition |
| A longer critical section | A `lock` around the test, the change, **and** every other access of the flag |

```csharp
private int _started;                                              // 0 = no, 1 = yes

public void Start()
{
    if (Interlocked.CompareExchange(ref _started, 1, 0) == 0)      // test and set: ONE atomic step
    {
        StartWorker();                                             // only the thread that won gets here
    }
}
```

`Interlocked` has no `bool` overload: use an `int` (or `uint`, `long`) and a named constant for each value.

## 🔧 Code fix

* **Add comment for code review**: inserts a comment that references the rule. Making the test and the change one atomic step (Interlocked, a lock, a signal) changes the design of the class, so no automatic rewrite is offered.

## ⚙ Options

All options are set in the `.editorconfig`, under `dotnet_diagnostic.DSA050.<key>`.

| Key | Default | Meaning |
|:----|:--------|:--------|
| `severity` | `warning` | The severity of the rule |
| `report_set_once` | `true` | Report `if (!flag) { flag = true; }` |
| `report_consume` | `true` | Report `if (flag) { flag = false; }` |
| `report_state_transitions` | `true` | Report `if (state == A) { state = B; }` |
| `report_volatile_fields` | `true` | Report the `volatile` fields too |
| `skip_inside_lock` | `true` | Do not report the code inside a `lock` statement |
| `skip_constructors` | `true` | Do not report the code of a constructor |
| `require_shared_access` | `true` | A private member is reported only when the field is shared (used by another member, static or volatile) |
| `excluded_type_name_patterns` | *(empty)* | Glob patterns of the type names to ignore |
| `excluded_namespace_patterns` | *(empty)* | Glob patterns of the namespaces to ignore |
| `excluded_base_types` | *(empty)* | Types whose descendants are ignored |
| `excluded_field_name_patterns` | *(empty)* | Glob patterns of the field names to ignore |
| `excluded_member_name_patterns` | *(empty)* | Glob patterns of the member names to ignore |
| `excluded_file_patterns` | `*.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs` | Glob patterns of the files to ignore |

```ini
[*.cs]
dotnet_diagnostic.DSA050.severity = warning
dotnet_diagnostic.DSA050.report_state_transitions = false
dotnet_diagnostic.DSA050.excluded_member_name_patterns = Initialize*
```

## 🔐 Security implications

A once-only guard that runs twice (initializing a security context, opening a connection, consuming a one-time token) or a state machine that makes a transition twice can corrupt state or double-spend a resource.

* **CWE-367** — [Time-of-check Time-of-use (TOCTOU) Race Condition](https://cwe.mitre.org/data/definitions/367.html)
* **CWE-362** — [Concurrent Execution using Shared Resource with Improper Synchronization ("Race Condition")](https://cwe.mitre.org/data/definitions/362.html)
* **CWE-820** — [Missing Synchronization](https://cwe.mitre.org/data/definitions/820.html)
