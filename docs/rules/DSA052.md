# DSA052

`FirstOrDefault` (or `SingleOrDefault`) whose element is only tested for existence: ask the real question with `Any`.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA052                                                                                        |
| Title        | Use Any instead of FirstOrDefault when the element is only tested for existence               |
| Category     | Performance                                                                                   |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ✅                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

```csharp
var customer = await _db.Customers.FirstOrDefaultAsync(c => c.Email == email, ct);   // DSA052
if (customer != null)
{
    return Conflict("The e-mail is already registered");
}
```

The code asks *"give me the customer"* and then throws the customer away: all it wanted to know is *"is there one?"*. The difference is not a matter of style:

| | `FirstOrDefaultAsync(...) != null` | `AnyAsync(...)` |
|:--|:--|:--|
| SQL | `SELECT TOP(1) [c].[Id], [c].[Name], [c].[Email], ... FROM [Customers] ...` | `SELECT CASE WHEN EXISTS (SELECT 1 FROM [Customers] ...) THEN 1 ELSE 0 END` |
| Transferred | every column of a row | one bit |
| Materialized | a whole entity | nothing |
| Change tracking (EF) | the entity is attached to the change tracker, for nothing | nothing |
| Intent | "I need this customer" | "does a customer exist?" |

In memory the cost is small (both stop at the first match), but the code still says something it does not mean, and an element that is produced and ignored is noise for the reader: *"what happens to it?"*.

The rule reports:

* the call that is compared with `null` right away: `q.FirstOrDefault(p) != null`, `== null`, `is null`, `is not null`, `is { }`, also `await q.FirstOrDefaultAsync(p, ct) != null` and with `.ConfigureAwait(false)`;
* the **local variable** that receives the result and is only ever compared with `null`:

```csharp
var customer = _db.Customers.FirstOrDefault(c => c.Email == email);   // DSA052
if (customer == null) { ... }
```

The methods are `FirstOrDefault`, `FirstOrDefaultAsync`, `SingleOrDefault` and `SingleOrDefaultAsync` (`included_methods` adds more, for example `LastOrDefault`). The async versions are reported only when the provider has the matching `AnyAsync` next to them (Entity Framework Core has it), so that the suggestion always exists.

### What is *not* reported (the element is used)

The rule is silent as soon as the element has any other use: if it is

* **returned** (`return item;`), **assigned** to a variable, a field, a property, an array, a tuple or a deconstruction;
* **accessed** (`item.Name`, `item?.Name`) or **passed** as an argument (also `ref` / `out`);
* used in a **pattern that looks inside** (`is Item i`, `is { Id: 1 }`), in an interpolated string, or compared with something other than `null`;
* **captured** by a lambda or a local function;
* **reassigned**, or tested for `null` and then used (`if (item == null) return; item.Do();`).

A variable that is never used is not reported either (that is not an existence test, it is an unused variable).

### Where `FirstOrDefault() != null` and `Any()` are *not* the same question

If the sequence can contain `null` elements, `FirstOrDefault() != null` is false when the **first element is a null**, while `Any()` is true. The same for a value type: `ints.FirstOrDefault() != 0` has nothing to do with the existence of an element. The rule therefore does not report:

* sequences of **value types** (`int`, structs, `int?`...) and of unconstrained generic types, where `default` is an element like the others;
* sequences of **`string`** and **`object`**, and of **nullable reference types** (`Item?`), where `null` elements are common (`skip_possibly_null_elements`, on by default).

Sequences of entities and DTOs (the normal case of a database query) are reported.

### `SingleOrDefault` is also a check

`SingleOrDefault` returns the element only if there is **exactly one** match and **throws** when there are more: it enforces an invariant. `Any` does not. When only the existence matters, `Any` is the right question; when the uniqueness is part of the design, make it explicit. The message of the rule says so for `SingleOrDefault`, and the code fix is labelled *"(drops the uniqueness check)"*.

## 🔐 Security implications

Loading a full row to test its existence amplifies the work of the data source for every request, and an endpoint that does it on user-controlled input is a cheap target for resource exhaustion.

* **CWE-1049** — [Excessive Data Query Operations in a Large Data Table](https://cwe.mitre.org/data/definitions/1049.html)
* **CWE-405** — [Asymmetric Resource Consumption (Amplification)](https://cwe.mitre.org/data/definitions/405.html)

## 🔦 Code sample

```csharp
public class Samples
{
    public void NotOk()
    {
        // this WILL trigger the rule: the customer is never used
        if (await db.Customers.FirstOrDefaultAsync(c => c.Email == email, ct) != null) { ... }
    }

    public void Ok()
    {
        // this WILL NOT trigger the rule: the customer is used
        var found = db.Customers.FirstOrDefault(c => c.Email == email);
        if (found == null) return NotFound();
        return Ok(found.Name);
    }
}
```

## ℹ️  Matched patterns (code is NOT OK)

```cs
// this WILL trigger the rule: the customer is never used
if (await db.Customers.FirstOrDefaultAsync(c => c.Email == email, ct) != null) { ... }

// this WILL trigger the rule: the variable is only compared with null
var customer = db.Customers.FirstOrDefault(c => c.Email == email);
if (customer == null) { ... }
```

## ✅ Not matched patterns (code is OK)

```cs
// this WILL NOT trigger the rule: the customer is used
var found = db.Customers.FirstOrDefault(c => c.Email == email);
if (found == null) return NotFound();
return Ok(found.Name);

// this WILL NOT trigger the rule: the customer is returned
return db.Customers.FirstOrDefault(c => c.Email == email);

// this WILL NOT trigger the rule: the elements can be null, FirstOrDefault() != null is not Any()
if (names.FirstOrDefault(n => n.Length > 3) != null) { ... }

// this WILL NOT trigger the rule: a value type, default is an element like the others
if (numbers.FirstOrDefault(n => n > 3) != 0) { ... }
```

## 🛠️ Included Code Fixer and Mitigation

*Use 'Any' instead of 'FirstOrDefault'* rewrites the test: the call keeps its predicate, type arguments and `CancellationToken`; `== null` becomes `!`; `await` and `ConfigureAwait` are kept.

```csharp
// before
var customer = await _db.Customers.FirstOrDefaultAsync(c => c.Email == email, ct);
if (customer != null) { ... }
// after
var customerExists = await _db.Customers.AnyAsync(c => c.Email == email, ct);
if (customerExists) { ... }
```

A variable becomes the boolean (`customer` → `customerExists`; a name already used in the member gets a number), an explicit type becomes `bool`, and every test of the variable is rewritten. *Fix all* rewrites all the tests of a document in one pass. The review comment is always offered.

The *Add comment for code review* action is always offered.

## ⚙️ Rule configuration

### Severity

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA052: Use Any instead of FirstOrDefault when the element is only tested for existence
# Possible values: error, warning, suggestion, silent, none
dotnet_diagnostic.DSA052.severity = warning
```

Every option below is optional. A missing, blank or malformed value is ignored and the default is used. Lists are comma-separated; a list **replaces** the default list.
