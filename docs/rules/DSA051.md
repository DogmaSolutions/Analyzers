# DSA051

A class without a `ToString()` override shows up as its type name in the debugger, in logs and in failed assertions.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA051                                                                                        |
| Title        | A class without a ToString() override shows up as its type name                               |
| Category     | Best Practice                                                                                 |
| Severity     | 💡 Suggestion                                                                                     |
| Refactoring available | ✅                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

`Object.ToString()` returns the full name of the type. An instance of a class that does not override it is printed like this, wherever it is printed:

```text
Assert.AreEqual failed. Expected:<MyApp.Orders.Order>. Actual:<MyApp.Orders.Order>.
Processing MyApp.Orders.Order
The order MyApp.Orders.Order was rejected
```

*Which* order? There is no way to tell: the debugger, the log, the exception message and the test report all show the same useless text for every instance. A `ToString()` that shows what identifies the instance turns each of those places into something readable, at the price of one line:

```text
Assert.AreEqual failed. Expected:<42>. Actual:<43>.
Processing 42
The order 42 was rejected
```

The rule reports a class (or struct, see `included_type_kinds`) that neither declares nor inherits a `ToString()`, and the code fix **generates it** with the heuristic below.

> The rule is about *observability*, not about behavior: a `ToString()` is not meant to be parsed or compared. Keep it short, free of side effects and free of secrets.

### The heuristic of the code fix

The generated `ToString()` is built from the members the class **declares** (properties and instance fields, all the parts of a `partial` class), in this order, stopping at the first step that has something to show:

| # | Members used | Generated text |
|:--|:-------------|:---------------|
| 1 | **The first name of the `well_known_names` list that the class has**, as a property or as a field (ignoring `_` and casing). The order of the list decides, not the order of the declarations; a property comes before the field that backs it | `$"{Id}"` (or `$"Id={Id}"` with `well_known_include_key`) |
| 2 | **All the public properties** | ``$"Total=`{Total}`, Currency=`{Currency}`"`` |
| 3 | **All the protected properties** (`protected`, `protected internal`, `private protected`) | `$"Total={Total}, Currency={Currency}"` |
| 4 | **All the fields** | `$"total={total}, currency={currency}"` |
| 5 | All the other properties (`internal`, `private`) | `$"Total={Total}, Currency={Currency}"` |
| - | Nothing to show: no properties, no fields | **no `ToString()` is generated** (only the review comment is offered) |

The default list of well known names is `Id`, `Key`, `Pk`, `Name`, `Value`, `FriendlyName`, `Description`, `FirstName`, `LastName`, `Surname`, `Email`, `Address`, `Url`, `Range`.

```csharp
public class Order                       public class Order
{                                        {
    public int Id { get; set; }              public int Id { get; set; }
    public decimal Total { get; set; }       public decimal Total { get; set; }
}                                    →
                                             public override string ToString() => $"{Id}";
                                         }

public class Money                       public class Money
{                                        {
    public decimal Amount { get; set; }     public decimal Amount { get; set; }
    public string Currency { get; set; }    public string Currency { get; set; }
}                                    →
                                             public override string ToString() => $"Amount=`{Amount}`, Currency=`{Currency}`";
                                         }
```

Notes on what the generated text never contains:

* **Secrets.** `ToString()` ends up in logs, so a member whose name contains `password`, `passwd`, `pwd`, `passphrase`, `secret`, `token`, `apikey`, `accesskey`, `privatekey`, `credential`, `connectionstring`, `cardnumber` or `cvv` (ignoring `_` and casing; configurable with `sensitive_name_patterns`) is left out of the lists of steps 2 to 5. If nothing else is left, the next step is tried. Review the generated text anyway: a name cannot tell everything (personal data, for example).
* Static members, constants, indexers, write-only properties, explicit interface implementations.
* Members that cannot be written in an interpolated string: pointers, function pointers, `ref struct`s.

The values are formatted with the current culture, as any interpolated string. A collection is printed as its type name (`System.Collections.Generic.List`1[System.String]`): if the content matters, write the `ToString()` by hand.

### What is never reported

* a class that declares a `ToString()` (also in another part of a `partial` class, also `new`), or whose base type (other than `object`) does (`consider_inherited_overrides`; with the option off, an inherited `ToString()` is still left alone when it is `sealed`, because it cannot be overridden);
* `static` classes, interfaces, enums and delegates, and records (the compiler generates their `ToString()`);
* structs, by default (`included_type_kinds = class, struct` to include them);
* classes that derive from `System.Attribute` (`excluded_base_types`);
* classes that have a `[DebuggerDisplay]` (they have a representation for the debugger already), generated code (`[GeneratedCode]`, `[CompilerGenerated]`) and generated files (`ignored_attributes`);
* the types of a **test project** (an assembly that references a test framework);
* types excluded by the options.

## 🔧 Configuration

| Option | Default | Description |
|:-------|:--------|:------------|
| `severity` | `suggestion` | The severity of the rule |
| `included_type_kinds` | `class` | The kinds of type that are looked at: `class`, `struct` |
| `include_abstract_classes` | `true` | Look at the abstract classes |
| `include_nested_types` | `true` | Look at the nested types |
| `min_data_members` | `0` | Report only the types with at least this number of instance properties and fields (`0`: also the types that have none, where no `ToString()` can be generated) |
| `consider_inherited_overrides` | `true` | A `ToString()` declared by a base type (other than `object`) is the type's own |
| `well_known_names` | `Id, Key, Pk, Name, Value, FriendlyName, Description, FirstName, LastName, Surname, Email, Address, Url, Range` | The names that identify an instance, in order of priority (ignoring `_` and casing) |
| `well_known_include_key` | `false` | Generate `Id={Id}` and not only `{Id}` for a well known member |
| `sensitive_name_patterns` | `password, passwd, pwd, passphrase, secret, token, apikey, accesskey, privatekey, credential, connectionstring, cardnumber, cvv` | Members whose name contains one of these (ignoring `_` and casing) are never written in the generated text |
| `max_members` | `0` | The most members the generated text lists (`0`: all) |
| `use_expression_body` | `true` | Generate `=> $"..."` and not a block with a `return` |
| `ignored_attributes` | `System.CodeDom.Compiler.GeneratedCodeAttribute, System.Runtime.CompilerServices.CompilerGeneratedAttribute, System.Diagnostics.DebuggerDisplayAttribute` | Types with one of these attributes (or contained in such a type) are not reported |
| `skip_test_assemblies` | `true` | Do not report the types of a test project |
| `test_assembly_names` | `xunit.core, xunit.v3.core, nunit.framework, Microsoft.VisualStudio.TestPlatform.TestFramework, MSTest.TestFramework, TUnit.Core` | The references that tell a project is a test project |
| `excluded_type_name_patterns` | *(empty)* | Glob patterns of the type names to ignore |
| `excluded_namespace_patterns` | *(empty)* | Glob patterns of the namespaces to ignore |
| `excluded_base_types` | `System.Attribute` | Types whose descendants are ignored |
| `excluded_file_patterns` | `*.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs` | Glob patterns of the files to ignore |

```ini
[*.cs]
# raise it when the team wants it enforced
dotnet_diagnostic.DSA051.severity = warning
dotnet_diagnostic.DSA051.min_data_members = 1
dotnet_diagnostic.DSA051.well_known_names = Id, Code, Title
dotnet_diagnostic.DSA051.excluded_type_name_patterns = *Dto, *Options
```

## 🔐 Security implications

When something goes wrong, the evidence is in the logs. A log line that says only `MyApp.Orders.Order` does not allow to trace what happened to which entity, which makes incidents harder to investigate. On the other hand `ToString()` is a way to leak data into the logs: the generated text skips the members that look like secrets, and the review of the result is part of the job.

* **CWE-778** — [Insufficient Logging](https://cwe.mitre.org/data/definitions/778.html)
* **CWE-532** — [Insertion of Sensitive Information into Log File](https://cwe.mitre.org/data/definitions/532.html)

## 🔦 Code sample

```csharp
// this WILL trigger the rule: it has an Id, the generated ToString() returns it
public class Order
{
    public int Id { get; set; }
    public decimal Total { get; set; }
}

// this WILL trigger the rule: nothing identifies it, the public properties are listed
public class Money
{
    public decimal Amount { get; set; }
    public string Currency { get; set; }
}

// this WILL NOT trigger the rule: it has a ToString()
public class Customer
{
    public string Name { get; set; }
    public override string ToString() => Name;
}

// this WILL NOT trigger the rule: the base class has a ToString()
public class VipCustomer : Customer
{
    public int Level { get; set; }
}

// this WILL NOT trigger the rule: a record has a generated ToString()
public record Point(int X, int Y);
```
