# DSA042

A namespace whose dotted path repeats the same segment — adjacent (`My.Project.Models.Models`) or not (`My.Project.Models.Abstractions.Models`). An echoed segment is a naming smell that makes the namespace harder to read and hints at a misplaced nesting level.

## 💡 Rationale

A namespace whose dotted path repeats the same segment is a naming smell: it reads awkwardly and usually signals a misplaced nesting level.

```csharp
namespace My.Cool.Project.Models.Models { }              // DSA042: "Models" repeated (adjacent)
namespace My.Cool.Project.Models.Abstractions.Models { } // DSA042: "Models" repeated (non-adjacent)
```

The comparison is **ordinal** (case-sensitive), so `My.models.Models` is not flagged. Nested declarations are evaluated by their effective full path: a declaration only reports a repetition among the segments it itself introduces, so a repetition inherited from an enclosing namespace is reported once, on the ancestor that introduced it, rather than re-reported by every nested declaration.

## 📖 Knowledge base

- [MITRE, CWE-1078: Inappropriate Source Code Style or Formatting](https://cwe.mitre.org/data/definitions/1078.html)

## 🔦 Code sample

```csharp
namespace My.Cool.Project.Models.Models    // this WILL trigger the rule: "Models" repeated
{
    public class Order { }
}

namespace My.Cool.Project.Models           // this WILL NOT trigger the rule: each segment distinct
{
    public class Customer { }
}
```

## ℹ️  Matched patterns (code is NOT OK)

```cs
// Adjacent repetition:
namespace My.Project.Models.Models { }

// Non-adjacent repetition:
namespace My.Project.Models.Abstractions.Models { }

// A repetition introduced by a nested declaration is flagged at the inner declaration:
namespace A.Models { namespace Models { } }
```

## ✅ Not matched patterns (code is OK)

```cs
// Each segment is distinct:
namespace My.Project.Models { }
namespace My.Project.Models.Abstractions { }

// Ordinal (case-sensitive) comparison — a case difference is not a repetition:
namespace My.models.Models { }
```

## 👉️ Rules of thumb for prevention and proactive posture

- Rename the offending segment, or flatten the namespace so each segment is distinct:

  ```csharp
  namespace My.Cool.Project.Models { }              // single, clear segment
  namespace My.Cool.Project.Models.Abstractions { } // distinct segments
  ```

- Treat a repeated segment as a prompt to reconsider the folder/namespace hierarchy: it often means a level of nesting is redundant.

## ⚙️ Rule configuration

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA042: Avoid repeating a segment in a namespace
dotnet_diagnostic.DSA042.severity = error
```
