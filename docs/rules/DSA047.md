# DSA047

A lock object must be private and never reassigned.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA047                                                                                        |
| Title        | A lock object must be private and never reassigned                                            |
| Category     | Code Smell                                                                                    |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ❌                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

A `lock` excludes the threads that lock **the very same object**. Two properties of the lock object follow from that, and both are routinely broken:

1. **It must never change.** If the field that holds the lock object is reassigned, a thread that locked the old object and a thread that locks the new one do not exclude each other.
2. **Nobody else must be able to lock on it.** If code outside of the class can reach the lock object, it can lock on it too, and its critical sections get entangled with yours: a caller that holds the lock while it waits for something that needs your class will deadlock, and nothing in your class shows why.

```csharp
public class MeasureSession
{
    private object _gate = new object();                // DSA047: reassigned below, and returned

    public object Gate                                  // the lock object leaves the class...
    {
        get { return _gate; }
        set { _gate = value; }                          // ...and can be replaced by anyone
    }

    public void Record(double value)
    {
        lock (_gate)                                    // DSA047
        {
            _samples.Add(value);
        }
    }
}
```

| Time | Thread A | Thread B | `_gate` |
|:-----|:---------|:---------|:--------|
| 1 | `lock (_gate)`: takes object **#1** | | #1 |
| 2 | | a caller sets `Gate = new object()` | #2 |
| 3 | | `lock (_gate)`: takes object **#2**, enters at once | #2 |
| 4 | still inside the critical section | inside the critical section too | #2 |

Both threads are inside "the same" critical section at the same time. The lock was there, and it protected nothing.

## ✅ What is reported

The lock is on a field or on an auto-property of the class (`x`, `this.x`), and:

| Scenario | The lock object is... | The lesson |
|:---------|:----------------------|:-----------|
| **Swapped** | a field that is written anywhere but in its declaration and directly in the constructors (a method, an accessor, a lambda or a local function of a constructor, `ref`/`out`, a tuple, another instance, a nested type...), or a property with a `set` accessor | Make it `readonly` / get-only and create the object once, so that every thread locks the same one |
| **Exposed** | a field that is `public`, `protected` or `protected internal`, or a field returned by a member with that reach (a property, a method, an indexer, an expression body), or a property whose getter has that reach | Keep the lock object `private` and never return it |
| **Swapped and exposed** | both | Both lessons in one message |

each one for fields and for auto-properties, so the rule has six messages. The diagnostic is located on the `lock (...)` header, and the message names the lock object and, when it is exposed, why (not private, returned by `Shared`, a property whose getter is not private).

`internal` members are seen as "outside of the class" only with `report_internal_locks`: they are reachable from the rest of the assembly, which is often the same team.

## 🚫 What is *not* reported

| Case | Why |
|:-----|:----|
| `private readonly` field, or a private get-only (or `init`-only) auto-property | This is the pattern the rule teaches |
| A private field assigned by the constructors only | Fixed once the object is built (the IDE0044 style rule suggests `readonly`) |
| A private field returned by a private member, passed to a method, compared, or captured by a lambda | Not reachable from outside |
| A non-auto property (computed, expression-bodied, with an accessor body) | It can return a different object on every call, and the rule cannot reason about it |
| `lock (this)`, `lock (typeof(X))`, `lock ("text")`, a local variable, a parameter, a method result, `other.field` | Not a lock object of the class. For `this`, a type or a string the CA2002 rule *Do not lock on objects with weak identity* applies |
| A lock object declared in another assembly, or a `const` | Not code of this project |
| Generated files | `*.Designer.cs`, `*.g.cs`... are ignored |

All the parts of a `partial` type are inspected.

## 🔧 Alternatives

```csharp
public class MeasureSession
{
    private readonly object _gate = new object();           // created once, private

    public void Record(double value)
    {
        lock (_gate)
        {
            _samples.Add(value);
        }
    }
}
```

| You want | Use |
|:---------|:----|
| Let a caller make several calls atomic | A method that does the whole operation inside the lock; or an object that the *caller* owns and passes in on construction |
| Replace the lock object | You cannot. Create a new instance of the class that owns a new lock |
| Wait and signal | `Monitor.Wait`/`Pulse` on the same private object, or a `SemaphoreSlim` / `ManualResetEventSlim` / `Channel<T>` |
| Lock in async code | `SemaphoreSlim` (`await WaitAsync()`): `lock` cannot contain an `await` |
| A modern lock | .NET 9: `System.Threading.Lock` in a `private readonly` field |

## 🔧 Code fix

* **Add comment for code review**: inserts a comment that references the rule. Making the field `readonly` or `private` changes who can swap or use the lock object, which is a design decision, so no automatic rewrite is offered.

## ⚙ Options

All options are set in the `.editorconfig`, under `dotnet_diagnostic.DSA047.<key>`.

| Key | Default | Meaning |
|:----|:--------|:--------|
| `severity` | `warning` | The severity of the rule |
| `report_swapped_locks` | `true` | Report the lock objects that are reassigned |
| `report_exposed_locks` | `true` | Report the lock objects that code outside the class can reach |
| `report_internal_locks` | `false` | Consider `internal` as outside of the class too |
| `report_fields` | `true` | Report the lock objects that are fields |
| `report_properties` | `true` | Report the lock objects that are auto-properties |
| `excluded_type_name_patterns` | *(empty)* | Glob patterns of the type names to ignore |
| `excluded_namespace_patterns` | *(empty)* | Glob patterns of the namespaces to ignore |
| `excluded_base_types` | *(empty)* | Types whose descendants are ignored |
| `excluded_lock_name_patterns` | *(empty)* | Glob patterns of the lock object names to ignore |
| `excluded_file_patterns` | `*.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs` | Glob patterns of the files to ignore |

```ini
[*.cs]
dotnet_diagnostic.DSA047.severity = warning
dotnet_diagnostic.DSA047.report_internal_locks = true
dotnet_diagnostic.DSA047.excluded_namespace_patterns = *.Legacy
```

## 🔐 Security implications

A lock that excludes nobody, or that an outsider can hold, turns a protected invariant into a race, or into a denial of service: a caller that locks the exposed object and never releases it blocks every thread that needs the class.

* **CWE-667** — [Improper Locking](https://cwe.mitre.org/data/definitions/667.html)
* **CWE-413** — [Improper Resource Locking](https://cwe.mitre.org/data/definitions/413.html)
* **CWE-820** — [Missing Synchronization](https://cwe.mitre.org/data/definitions/820.html)
