# DSA044

A call to `Console.Write*` or `Debug.Write*` in code that has a logger available. The text written to the console bypasses the logging pipeline: it has no level, category, timestamp or structure, it is lost where there is no console (services, containers, IIS, serverless), and it can neither be filtered nor shipped to the configured sinks. When a logger is at hand, use it.

|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA044                                                                                        |
| Title        | Use the available logger instead of Console.Write* or Debug.Write*                            |
| Category     | Best Practice                                                                                 |
| Severity     | 💡 Suggestion                                                                                  |
| Refactoring available | ✅ (for Microsoft.Extensions.Logging loggers)                                                  |
| Code-review tools available | ✅                                                                                             |

## 💡 Rationale

`Console.WriteLine("Imported 12 invoices")` is a log written by hand: no severity, no source, no time, no structure, and no way to turn it off in production or to send it anywhere. `Debug.WriteLine` is no better: it vanishes from release builds, exactly where the information is needed. In a class that already has a logger, such a call is almost always a leftover of debugging or a habit, and the logger is one `_logger.LogInformation(...)` away.

The rule reports a call to a member of a **flagged type** (default: `System.Console` and `System.Diagnostics.Debug`) whose name matches a **flagged member** pattern (default: `Write*`, i.e. `Write`, `WriteLine`, `WriteIf`, `WriteLineIf`), including the calls on `Console.Out` and `Console.Error`, when a **logger is available at that point** of the code.

A logger is available when the call can reach one:

* a **parameter** of the method, constructor, lambda or local function that holds the call;
* a **field or property** of the class, own or inherited from a base class (not private); in a static member only a static one counts;
* a parameter of the **primary constructor** of the class, in an instance member;
* a **static logger the class already calls** (by default `Serilog.Log`), anywhere in the class.

The loggers recognized by default are those of the most common technologies; a concrete logger is recognized through its interface:

| Technology | Types |
|:--|:--|
| Microsoft.Extensions.Logging | `ILogger`, `ILogger<T>`, `ILoggerFactory` |
| Serilog | `Serilog.ILogger` (and the static `Serilog.Log`) |
| NLog | `NLog.ILogger`, `NLog.Logger` |
| log4net | `log4net.ILog` |
| Castle | `Castle.Core.Logging.ILogger` |
| Common.Logging | `Common.Logging.ILog` |
| NServiceBus | `NServiceBus.Logging.ILog` |
| Akka.NET | `Akka.Event.ILoggingAdapter` |
| System.Diagnostics | `TraceSource` |

Nothing is reported where no logger is available, and the rule is silent in `Program`, in `Main`, and in members that also read the console (a prompt or a menu talks to a person: it is not a log). All of this is configurable.

## 🔐 Security implications

* **CWE-778** — [Insufficient Logging](https://cwe.mitre.org/data/definitions/778.html): events written to the console instead of the log are missing from the audit trail, the monitoring and the alerts.

Console and debug output also tends to carry the data that must not be logged (tokens, personal data, exception details) to places nobody governs: standard output is captured by container runtimes and CI systems with no retention or redaction policy.

## 🔦 Code sample

```csharp
public class InvoiceImporter
{
    private readonly ILogger<InvoiceImporter> _logger;

    public InvoiceImporter(ILogger<InvoiceImporter> logger) => _logger = logger;

    public void Import(string file, int count)
    {
        // this WILL trigger the rule: a logger is available
        Console.WriteLine($"Imported {count} invoices from {file}");

        // this WILL trigger the rule too
        Debug.WriteLine("import done");
        Console.Error.WriteLine("import failed");

        // this WILL NOT trigger the rule
        _logger.LogInformation("Imported {Count} invoices from {File}", count, file);
    }
}
```

## ℹ️  Matched patterns (code is NOT OK)

```cs
// Console.Write, Console.WriteLine (any overload), also through "using static System.Console"
// Console.Out.Write*, Console.Error.Write*
// Debug.Write, Debug.WriteLine, Debug.WriteIf, Debug.WriteLineIf
// ... when the code can reach a logger (parameter, field/property, primary constructor, static logger already called in the class)
```

## ✅ Not matched patterns (code is OK)

```cs
// There is no logger available at that point:
//   - the class has none, or only an instance one while the call is in a static member
//   - a logger passed to the constructor and not stored, used in another method
// The call is not flagged: Console.ReadLine, Console.Beep, Debug.Assert, Trace.WriteLine (unless added to flagged_types), a writer that is not Console.Out/Error
// The call is in a class named Program, in a method named Main (default exclusions)
// The member also reads the console (Console.ReadLine, Console.ReadKey, ...): it is a dialog with a person   -> skip_interactive_members
// The type, namespace, member or file matches an exclusion pattern
// Generated code
```

## 🛠️ Included Code Fixer and Mitigation

When the available logger is a Microsoft.Extensions.Logging one (`ILogger`, `ILogger<T>`), the code fixer **replaces the call with a call of the logger** and adds `using Microsoft.Extensions.Logging;` if it is missing:

| Before | After |
|:--|:--|
| `Console.WriteLine("hello")` | `_logger.LogInformation("hello")` |
| `Console.WriteLine("n={0}", count)` | `_logger.LogInformation("n={0}", count)` |
| `Console.WriteLine(file.Name)` | `_logger.LogInformation("{Value}", file.Name)` |
| `Console.WriteLine($"read {count:N0} of {file.Name}")` | `_logger.LogInformation("read {Count:N0} of {Name}", count, file.Name)` |
| `Debug.WriteLine("d")` | `_logger.LogDebug("d")` |
| `Console.Error.WriteLine("e")` | `_logger.LogError("e")` |

* `Console.Write*` and `Console.Out.Write*` become `LogInformation`, `Debug.Write*` become `LogDebug`, `Console.Error.Write*` become `LogError`.
* An interpolated string becomes a message template: each hole is named after its identifier (`{Count}`, `{Name}`), keeps its format (`:N0`), and its expression becomes an argument. An alignment (`{count,5}`), a verbatim or raw string, or an expression that is not a name keeps the whole text as a single `{Value}`.
* No replacement is offered when there is no obvious equivalent (no argument, a character buffer, named arguments) or when the logger is of another technology (Serilog, NLog, log4net, ...) or an `ILoggerFactory`: their APIs differ too much for a safe mechanical fix.

The *Add comment for code review* action is always offered.

## ⚙️ Rule configuration

### Severity

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA044: Use the available logger instead of Console.Write* or Debug.Write*
dotnet_diagnostic.DSA044.severity = warning
```

Every option below is optional. A missing, blank or malformed value is ignored and the default is used. Lists are comma-separated; a list **replaces** the default list.

### Which calls

```ini
# Types whose members are flagged, by full name. Default: System.Console, System.Diagnostics.Debug
# Add System.Diagnostics.Trace to flag Trace.Write* too.
dotnet_diagnostic.DSA044.flagged_types = System.Console, System.Diagnostics.Debug, System.Diagnostics.Trace

# Glob patterns (* wildcard, case-insensitive) of the names of the flagged members. Default: Write*
dotnet_diagnostic.DSA044.flagged_members = Write*

# Console.Out.* and Console.Error.* are flagged like Console.*. Requires System.Console among the flagged types. Default true.
dotnet_diagnostic.DSA044.include_console_streams = true
```

### What counts as a logger

```ini
# Logging types, by full name without generic arity. A type that implements or derives from one of them is a logger too.
# Default: Microsoft.Extensions.Logging.ILogger, Microsoft.Extensions.Logging.ILoggerFactory, Serilog.ILogger, NLog.ILogger,
# log4net.ILog, Castle.Core.Logging.ILogger, Common.Logging.ILog, NServiceBus.Logging.ILog, Akka.Event.ILoggingAdapter,
# System.Diagnostics.TraceSource
dotnet_diagnostic.DSA044.logger_types = Microsoft.Extensions.Logging.ILogger, MyCompany.Diagnostics.IAppLogger

# Namespaces (and child namespaces) whose types are all loggers. Default: none.
dotnet_diagnostic.DSA044.logger_namespaces = MyCompany.Logging

# A logger declared in a base class (field or property that is not private) counts. Default true.
dotnet_diagnostic.DSA044.accept_inherited_logger = true

# A logger received as a parameter of the method, constructor, lambda or local function counts. Default true.
dotnet_diagnostic.DSA044.accept_logger_parameters = true

# The logger must be reachable from the call: in a static member only a static logger counts. false: any logger of the class counts. Default true.
dotnet_diagnostic.DSA044.require_accessible_logger = true

# A class that already calls a static logger has a logger available everywhere. Default true.
dotnet_diagnostic.DSA044.accept_static_logger_calls = true

# The static loggers, by full name. Default: Serilog.Log
dotnet_diagnostic.DSA044.static_logger_types = Serilog.Log
```

### Where the writes are accepted

```ini
# A member that also reads the console (Console.ReadLine, ReadKey, Read) talks to a person: its writes are not logs. Default true.
dotnet_diagnostic.DSA044.skip_interactive_members = true

# Types whose name matches one of these patterns are not checked. Default: Program
dotnet_diagnostic.DSA044.excluded_type_name_patterns = Program, *Cli, *Command

# Members whose name matches one of these patterns are not checked. Default: Main
dotnet_diagnostic.DSA044.excluded_member_name_patterns = Main, Print*

# Types declared in a namespace that matches one of these patterns are not checked. Default: none
dotnet_diagnostic.DSA044.excluded_namespace_patterns = *.Tests, *.Tools

# Code in a file whose name matches one of these patterns is not checked.
# Default: *.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs
dotnet_diagnostic.DSA044.excluded_file_patterns = *.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs
```

### Example: a command-line tool

A tool whose job is to print to the console, with a logger for diagnostics, can keep its output and still be checked everywhere else:

```ini
dotnet_diagnostic.DSA044.excluded_type_name_patterns = Program, *Command, *Printer
```
