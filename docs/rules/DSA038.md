# DSA038

Avoid seeding `Random` with a time-based or constant value.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA038                                                                                        |
| Title        | Avoid seeding Random with a time-based or constant value                                      |
| Category     | Bug                                                                                           |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ❌                                                                                             |
| Code-review tools available | ❌                                                                                             |
| Is enabled   | ✅                                                                                             |

## Rationale

`new Random(seed)` is almost always a mistake in one of two ways.

**Time-based seed** — `new Random(Environment.TickCount)`, `new Random((int)DateTime.UtcNow.Ticks)`, etc. This merely reproduces what the parameterless `new Random()` already does internally, but worse: the clock has coarse resolution, so several `Random` instances created within the **same tick** — the classic "new `Random` inside a loop" bug — receive the **same seed** and emit the **identical sequence**.

```csharp
// BUG: every instance created in the same millisecond returns the same numbers.
for (int i = 0; i < 100; i++)
{
    var rnd = new Random(Environment.TickCount);
    Console.WriteLine(rnd.Next());
}
```

**Constant seed** — `new Random(42)`. The sequence is fully deterministic and predictable. That is occasionally desirable for a reproducible simulation or a unit test, but is a defect in production code (and never a source of security-grade randomness).

### Fix

Use the parameterless constructor, which is seeded for you with a high-entropy, per-instance value (on modern .NET), or the shared thread-safe instance on .NET 6+:

```csharp
var rnd = new Random();      // correct
int n = Random.Shared.Next(); // .NET 6+, thread-safe
```

For security-sensitive values (tokens, keys, salts) do not use `System.Random` at all — use `System.Security.Cryptography.RandomNumberGenerator`.

## Matched patterns (code is NOT OK)

```cs
new Random(Environment.TickCount);
new Random(Environment.TickCount64);
new Random((int)DateTime.Now.Ticks);
new Random((int)DateTime.UtcNow.Ticks);
new Random(unchecked((int)DateTimeOffset.UtcNow.Ticks));
new Random((int)System.Diagnostics.Stopwatch.GetTimestamp());
new Random(42);                 // compile-time constant
const int Seed = 7; new Random(Seed);
```

## Not matched patterns (code is OK)

```cs
new Random();                   // parameterless — the recommended form
new Random(GetSeedFromConfig()); // non-constant, non-time-based runtime value
new Random(userSuppliedSeed);   // a parameter is neither constant nor time-based
```

## Rule configuration

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA038: Avoid seeding Random with a time-based or constant value
dotnet_diagnostic.DSA038.severity = warning
```

If a specific area legitimately needs a reproducible constant seed (e.g. a test project), scope the severity down for that path:

```ini
[tests/**.cs]
dotnet_diagnostic.DSA038.severity = none
```
