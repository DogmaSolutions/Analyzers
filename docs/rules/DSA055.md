# DSA055

A key or an identifier is compared with zero by equality: a negative value is as invalid as zero.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA055                                                                                        |
| Title        | A key or an identifier is compared with zero by equality: a negative value is as invalid as zero |
| Category     | Code Smell                                                                                    |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ✅                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

A primary key or an entity identifier is not expected to be zero or negative. A validity check written with `!= 0` accepts every negative value, and a check written with `== 0` rejects zero only:

```csharp
protected override bool IsValidKey(long resolvedKey)
{
    return resolvedKey != 0;        // (DSA055) -1 is "valid"
}
```

It is not wrong per se, but it is fragile, and often a bug in waiting: a lookup that returns `-1` for "not found", an overflow, a sentinel or a value that comes from a bad conversion goes through the check as if it were a key. The check should say what the domain says:

| You wrote | The domain says | Write |
|:----------|:----------------|:------|
| `id != 0` | a valid key is positive | `id > 0` |
| `id == 0` | an invalid key is zero **or negative** | `id <= 0` |

## ✅ What is reported

A comparison with the literal `0` (`0`, `0L`, `0u`, `0x0`, `0b0`, in parentheses or not, on either side), made with `==`, `!=`, `is 0` or `is not 0`, of a value that is:

* a **variable, a parameter, a field or a property** (a local, a lambda parameter, `this.OrderId`, `order.CustomerId`, `Worker.LastId`),
* of an **integral type**: `sbyte`, `byte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`,
* with a **key name**, case sensitive: a name that **ends with** `Id` or `Key` (`userId`, `ResolvedKey`), or that is exactly `id`, `key`, `Id`, `Key`, `Pk`, `pk` or `primaryKey`.

The message depends on the case, and says the type:

| Case | Message |
|:-----|:--------|
| `!= 0`, signed type | also true for every negative value: *did you mean to write `> 0`?* |
| `== 0`, signed type | false for every negative value: *did you mean to write `<= 0`?* |
| `!= 0`, unsigned type | the value cannot be negative, so `!= 0` is the same as `> 0`: writing `> 0` says what the code means, and stays right if the type becomes signed |
| `== 0`, unsigned type | same as `<= 0`, for the same reason |

## 🚫 What is *not* reported

| Case | Why |
|:-----|:----|
| A name that is not a key name: `Valid`, `paid`, `monkey`, `Hybrid`, `ID`, `PK`, `_id`, `primarykey`, `ids` | The name rule is case sensitive and exact |
| `string`, `Guid`, `double`, `decimal`, `char`, enums, `object`, nullable (`long?`), `nint`/`nuint` | Not integral types of a fixed width (a nullable value is `null` before it is zero; the width of a native integer depends on the platform) |
| A method call (`GetId() != 0`), an indexer or an element (`ids[0] != 0`), a cast, a conditional access (`w?.Id != 0`) | Not a variable, a parameter, a field or a property |
| A constant (`const long NoId = 0;`) and a comparison with something else than the literal zero (`id != None`, `id != default`, `id != 0.0`, `id != parentId`) | The intent is explicit, or it is not a check against zero |
| `id > 0`, `id <= 0`, `id is 1`, `id is > 0` | Already the right comparison, or another value |
| Generated files | `*.Designer.cs`, `*.g.cs`... are ignored |

## 🔧 Code fix

* **Compare with `> 0` / `<= 0`**: replaces the comparison (`x != 0`, `0 == x`, `x is 0`, `x is not 0`) by `x > 0` or `x <= 0`. For a signed type it **changes what the code does** for negative values, which is the point: review it. For an unsigned type the result is equivalent.
* **Add comment for code review**: inserts a comment that references the rule.

## ⚙ Options

All options are set in the `.editorconfig`, under `dotnet_diagnostic.DSA055.<key>`.

| Key | Default | Meaning |
|:----|:--------|:--------|
| `severity` | `warning` | The severity of the rule |
| `report_equality` | `true` | Report `== 0` and `is 0` too; if `false`, only `!= 0` and `is not 0` |
| `report_members` | `true` | Report fields and properties; if `false`, only locals and parameters |
| `report_unsigned_types` | `true` | Report the unsigned types (where `!= 0` and `> 0` are the same) |
| `key_name_suffixes` | `Id, Key` | The names that end with one of these are keys (case sensitive) |
| `key_exact_names` | `id, key, Id, Key, Pk, pk, primaryKey` | The names that are keys (case sensitive) |
| `excluded_name_patterns` | *(empty)* | Glob patterns of the variable names to ignore |
| `excluded_type_name_patterns` | *(empty)* | Glob patterns of the type names to ignore |
| `excluded_namespace_patterns` | *(empty)* | Glob patterns of the namespaces to ignore |
| `excluded_base_types` | *(empty)* | Types whose descendants are ignored |
| `excluded_member_name_patterns` | *(empty)* | Glob patterns of the member names to ignore |
| `excluded_file_patterns` | `*.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs` | Glob patterns of the files to ignore |

```ini
[*.cs]
dotnet_diagnostic.DSA055.severity = warning
dotnet_diagnostic.DSA055.key_name_suffixes = Id, Key, Code
dotnet_diagnostic.DSA055.report_unsigned_types = false
```
