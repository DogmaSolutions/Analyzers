# DSA056

A test fixture is not excluded from the code coverage.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA056                                                                                        |
| Title        | A test fixture is not excluded from the code coverage                                         |
| Category     | Code Smell                                                                                    |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ✅                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

The code coverage is meant to tell how much of the **product** code the tests run. A test fixture is not product code: if it is measured too, its own lines (all executed, by definition) raise the percentage and hide the product code that no test runs.

```csharp
public class OrderTests                 // (DSA056) measured: 100% covered by itself
{
    [Fact]
    public void Total_is_the_sum() { ... }
}
```

```csharp
[global::System.Diagnostics.CodeAnalysis.ExcludeFromCodeCoverage]
public class OrderTests
{
    [Fact]
    public void Total_is_the_sum() { ... }
}
```

If the coverage of the tests is wanted (for instance to find tests that are never run), disable the rule, or exclude the type with `excluded_type_name_patterns`.

## ✅ What is reported

A **class** (not a static class, a struct or an interface) that is a **test fixture**, and has no exclusion attribute:

* it is a fixture when the class, or **one of its methods**, has an attribute of **NUnit** (`TestFixture`, `Test`, `TestCase`, `TestCaseSource`, `Theory`, `SetUp`, `TearDown`, `OneTimeSetUp`, `OneTimeTearDown`), **xUnit** (`Fact`, `Theory`), **MSTest** (`TestClass`, `TestMethod`, `DataTestMethod`, `TestInitialize`, `TestCleanup`, `ClassInitialize`, `ClassCleanup`) or **TUnit** (`Test`, `Before`, `After`), or an attribute **derived** from one of them (`[SkippableFact]`);
* abstract base fixtures and nested fixtures are reported too; a partial class is reported once.

The diagnostic is located on the name of the class.

## 🚫 What is *not* reported

| Case | Why |
|:-----|:----|
| A project that references no test framework (`xunit.core`, `xunit.v3.core`, `nunit.framework`, `MSTest.TestFramework`, `Microsoft.VisualStudio.TestPlatform.TestFramework`, `Microsoft.VisualStudio.QualityTools.UnitTestFramework`, `TUnit.Core`) | It has no test fixture: the rule does not even start, and costs nothing |
| A class with `[ExcludeFromCodeCoverage]` (on any part of a partial class) | Already done |
| An assembly with `[assembly: ExcludeFromCodeCoverage]` | Every type is excluded |
| Helpers, builders, fakes: classes with no test attribute on them or on their methods; a class that derives from a fixture but has no test of its own | Not test fixtures |
| Static classes, structs, interfaces, enums | Not fixtures of a framework |
| Generated files | `*.Designer.cs`, `*.g.cs`... are ignored |

A nested fixture is **not** covered by the attribute of the class that contains it: the attribute is not inherited and does not apply to the nested types, so the nested fixture is reported on its own.

## 🔧 Code fix

* **Exclude the test fixture from the code coverage**: adds `[global::System.Diagnostics.CodeAnalysis.ExcludeFromCodeCoverage]` above the class (the comments of the class stay above it).
* **Add comment for code review**: inserts a comment that references the rule.

## 🔁 Alternatives

| You want | Do |
|:---------|:---|
| To exclude **the whole test project**, once | `[assembly: ExcludeFromCodeCoverage]` in the project (the attribute can be applied to an assembly from **.NET 5**; on older frameworks it can only be applied to a type, a method, a property or an event). The rule then stays silent for the whole project |
| To leave the test projects out in the **configuration of the coverage tool** | Exclude the assembly there (for example `ExcludeByFile` / `Exclude` of Coverlet) and disable this rule |
| To keep the attribute on **some** fixtures only | `excluded_type_name_patterns`, `excluded_namespace_patterns`, `excluded_base_types`, `excluded_file_patterns` |

[DSA045](DSA045.md) is the opposite rule (the attribute on a class that has logic): it does not look at the test assemblies by default (`skip_test_assemblies`), so the two do not contradict each other.

## ⚙ Options

All options are set in the `.editorconfig`, under `dotnet_diagnostic.DSA056.<key>`.

| Key | Default | Meaning |
|:----|:--------|:--------|
| `severity` | `warning` | The severity of the rule |
| `test_attributes` | The attributes listed above | Full names of the attributes that make a class a test fixture (with or without the `Attribute` suffix; the attributes derived from them count too). The rule starts only in a project that references one of the test frameworks above |
| `exclusion_attributes` | `System.Diagnostics.CodeAnalysis.ExcludeFromCodeCoverageAttribute` | Full names of the attributes that exclude a type from the coverage (the assembly-level check looks for the default one) |
| `excluded_type_name_patterns` | *(empty)* | Glob patterns of the type names to ignore |
| `excluded_namespace_patterns` | *(empty)* | Glob patterns of the namespaces to ignore |
| `excluded_base_types` | *(empty)* | Types whose descendants are ignored |
| `excluded_file_patterns` | `*.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs` | Glob patterns of the files to ignore |

```ini
[*.cs]
dotnet_diagnostic.DSA056.severity = warning
dotnet_diagnostic.DSA056.excluded_namespace_patterns = *.Integration
```
