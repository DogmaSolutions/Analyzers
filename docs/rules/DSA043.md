# DSA043

A complex class that neither injects nor uses a logger. A class that is large or branchy, and that catches exceptions, awaits, throws or calls into I/O, is where production incidents are diagnosed; without a single log entry its behavior cannot be observed. What counts as "complex", which classes are checked and what counts as a logger are all configurable.

## 💡 Rationale

When something goes wrong in production, logs are often the only evidence. A small mapper or a DTO has nothing to say, but a class with many decisions, error handling, asynchronous calls or I/O is exactly where failures happen and where the *why* is needed. If such a class has no logger, nothing it does can be traced, and its failures are invisible or swallowed.

The rule measures the class (all the parts of a `partial` class together, nested types excluded) and reports it when **both** conditions are true:

1. **It is complex enough**: at least one of the enabled thresholds is reached (all of them, if `require_all_thresholds` is set) — total cyclomatic complexity, complexity of the most complex method, lines of code, number of methods, number of constructor parameters.
2. **It does something worth logging about** (unless `require_activity` is `false`): it contains a `catch` block, an `await`, a `throw`, or a call into one of the configured namespaces (HTTP, I/O, database, messaging, ...).

and the class has **no logger**: it neither

* **declares** one — a field, a property or a constructor parameter (a primary constructor included) whose type is a logging type, own or inherited from a base class; nor
* **uses** one — a method, lambda or local function parameter, a local variable, a call to a logging type (`LogInformation`, `LoggerMessage.Define`, ...), the creation of a logging object (`new NullLogger<T>()`), a service resolved as a logger (`GetService<ILogger<T>>()`), or a logging attribute (`[LoggerMessage]`).

A **logging type** is a type that lives in one of the `logger_namespaces` (default `Microsoft.Extensions.Logging`: `ILogger`, `ILogger<T>`, `ILoggerFactory`, `LoggerExtensions`, `LoggerMessage`, ...), one of the additional `logger_types`, or a type that implements or derives from one of them.

If the compilation does not reference any logging type, nothing is reported: there is no logger the class could inject.

The check is cheap: the cost is a few symbol lookups per class, the measure of a class is a single syntax walk, and the semantic model is only asked for the classes that are complex, active and without a logger declaration.

## 🔐 Security implications

* **CWE-778** — [Insufficient Logging](https://cwe.mitre.org/data/definitions/778.html): security-relevant and failure events that are not logged cannot be detected, investigated or audited.
* **OWASP Top 10, A09:2021** — [Security Logging and Monitoring Failures](https://owasp.org/Top10/A09_2021-Security_Logging_and_Monitoring_Failures/).

Without logs, attacks and malfunctions in the most complex code of the application go unnoticed.

## 🔦 Code sample

```csharp
using Microsoft.Extensions.Logging;

// this WILL trigger the rule: complex, handles errors and I/O, and has no logger
public class InvoiceImporter
{
    private readonly HttpClient _http;

    public InvoiceImporter(HttpClient http) => _http = http;

    public async Task<int> ImportAsync(IEnumerable<string> urls)
    {
        var imported = 0;
        foreach (var url in urls)
        {
            try
            {
                var body = await _http.GetStringAsync(url);
                if (body.Length > 0 && !body.StartsWith("<")) { imported++; }
                // ... many more decisions
            }
            catch (HttpRequestException)
            {
                // the failure is swallowed and nobody will ever know
            }
        }

        return imported;
    }
}

// this WILL NOT trigger the rule: the class injects a logger
public class InvoiceImporter_Ok
{
    private readonly HttpClient _http;
    private readonly ILogger<InvoiceImporter_Ok> _logger;

    public InvoiceImporter_Ok(HttpClient http, ILogger<InvoiceImporter_Ok> logger)
    {
        _http = http;
        _logger = logger;
    }

    // ... the same body, with _logger.LogWarning(ex, "Cannot import {Url}", url) in the catch block
}
```

## ℹ️  Matched patterns (code is NOT OK)

```cs
// A class whose total cyclomatic complexity, most complex method, lines of code, ... reach the configured thresholds,
// that contains a catch / await / throw or calls into I/O, and that has no logger:
public class OrderProcessor { /* complex, with try/catch, and no ILogger anywhere */ }

// The parts of a partial class are measured together; the diagnostic is reported on the first declaration:
public partial class OrderProcessor { /* part 1 */ }
public partial class OrderProcessor { /* part 2 */ }
```

## ✅ Not matched patterns (code is OK)

```cs
// The class is not complex enough (below every enabled threshold)
// The class does nothing worth logging about (no catch / await / throw / call into the activity namespaces)
// The class injects a logger: ILogger, ILogger<T>, ILoggerFactory as field, property or constructor parameter (primary constructors included)
// The logger is inherited from a base class (field or property, not private)               -> accept_inherited_logger
// The logger comes as a parameter of a method, lambda or local function                    -> accept_logger_parameters
// The class uses LoggerMessage.Define, [LoggerMessage], a logger local variable, GetService<ILogger<T>>(), ...
// The class is a static class, abstract class, nested type, struct or record                -> include_* / included_type_kinds
// The class derives from System.Exception or System.Attribute, or from any excluded base type -> excluded_base_types
// The name of the class matches *Dto, *Options, *Mapper, *Validator, ...                    -> excluded_type_name_patterns
// The class lives in a *.Migrations namespace                                               -> excluded_namespace_patterns
// The class is in a generated file (*.Designer.cs, *.g.cs, ...)                             -> excluded_file_patterns
// The compilation does not reference any logging type
```

## 👉️ Rules of thumb for prevention and proactive posture

- Inject `ILogger<T>` (with `T` the class itself) in every service, handler, controller, background service and repository.
- Log in the `catch` blocks (and then rethrow, or handle): a swallowed exception with no log is the worst case.
- Use [`LoggerMessage`](https://learn.microsoft.com/dotnet/core/extensions/high-performance-logging) source generation for hot paths.
- Do not log secrets or personal data.

## 🛠️ Included Code Fixer and Mitigation

Adding a logger changes the constructor signature, which breaks every caller (tests and dependency-injection registrations that build the class by hand), so the rule offers no automatic fix. It offers the *Add comment for code review* action only.

## 📝 Included tools for code review

The `[DSA043] Add comment for code review` action inserts a structured block comment above the class. The comment includes the rule ID, enriched category, title with documentation link, and relevant external references.

## ⚙️ Rule configuration

### Severity

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA043: Complex class neither injects nor uses a logger
dotnet_diagnostic.DSA043.severity = warning
```

Every option below is optional. A missing, blank, malformed or out-of-range value is ignored and the default is used. Lists are comma-separated.

### Thresholds: when is a class "complex"?

Each threshold can be turned off by setting it to `0`. A class is a target when **any** of the enabled thresholds is reached; set `require_all_thresholds = true` to require **all** of them. If every threshold is `0`, no class is ever a target.

```ini
# Total cyclomatic complexity of the class: the sum over its methods, constructors, operators and accessors, all the
# parts of a partial class together. Decision points: if, for, foreach, while, do, case, switch expression arms, catch (and
# its when filter), ?:, &&, ||, ??, ??=, and/or patterns. Default 30.
dotnet_diagnostic.DSA043.min_cyclomatic_complexity = 30

# Cyclomatic complexity of the most complex single method (constructors, operators, accessors included). Default 15.
dotnet_diagnostic.DSA043.min_method_complexity = 15

# Lines of code of the class (all the parts of a partial class). Default 200.
dotnet_diagnostic.DSA043.min_lines = 200

# Number of methods and operators. Default 0 (criterion disabled).
dotnet_diagnostic.DSA043.min_methods = 0

# Parameters of the constructor with the most parameters, a primary constructor included. A long list of dependencies is a
# sign of a class that does too much. Default 0 (criterion disabled).
dotnet_diagnostic.DSA043.min_constructor_parameters = 0

# true: all the enabled thresholds must be reached. false (default): any of them is enough.
dotnet_diagnostic.DSA043.require_all_thresholds = false

# Count the blank lines in min_lines. Default false.
dotnet_diagnostic.DSA043.count_blank_lines = false
```

### Activity: does the class do something worth logging about?

```ini
# true (default): the class must also contain one of the activity kinds below. false: the thresholds alone are enough.
dotnet_diagnostic.DSA043.require_activity = true

# Which operations make a class worth logging about: catch (a catch block), await, throw (a throw statement or expression),
# call (a call or object creation of a type in one of the activity namespaces). Default: catch, await, call.
dotnet_diagnostic.DSA043.activity_kinds = catch, await, call

# Namespaces (and their child namespaces) whose types count as activity for the "call" kind. Replaces the default list.
# Default: System.Net.Http, System.Net.Sockets, System.Net.Mail, System.IO, System.Data, Microsoft.Data,
# Microsoft.EntityFrameworkCore, Dapper, Npgsql, MySql, Oracle, MongoDB, StackExchange.Redis, Azure, Amazon, RabbitMQ,
# Confluent.Kafka, MassTransit
dotnet_diagnostic.DSA043.activity_namespaces = System.Net.Http, System.IO, Microsoft.EntityFrameworkCore
```

### What counts as a logger

```ini
# Namespaces (and their child namespaces) of the logging types: a type declared there, or implementing or deriving from
# one, is a logger. Replaces the default list. Default: Microsoft.Extensions.Logging
# Add Serilog, NLog, ... here to accept the other logging libraries.
dotnet_diagnostic.DSA043.logger_namespaces = Microsoft.Extensions.Logging, Serilog

# Additional logging types, by full name without generic arity (e.g. your own logging abstraction). Default: none.
dotnet_diagnostic.DSA043.logger_types = MyCompany.Diagnostics.IAppLogger

# A logger declared in a base class (field or property that is not private) counts. Default true.
dotnet_diagnostic.DSA043.accept_inherited_logger = true

# A logger received as a parameter of a method, lambda or local function counts as using it. Default true.
dotnet_diagnostic.DSA043.accept_logger_parameters = true
```

### Which classes are checked

```ini
# Kinds of type that are checked: class, record, struct, "record struct". Default: class.
dotnet_diagnostic.DSA043.included_type_kinds = class, record

# Check static classes. Default false.
dotnet_diagnostic.DSA043.include_static_classes = false

# Check abstract classes. Default false.
dotnet_diagnostic.DSA043.include_abstract_classes = false

# Check nested types. Default false.
dotnet_diagnostic.DSA043.include_nested_types = false

# Types that derive (directly or indirectly) from one of these are not checked. Full names. Replaces the default list.
# Default: System.Exception, System.Attribute
dotnet_diagnostic.DSA043.excluded_base_types = System.Exception, System.Attribute, Microsoft.EntityFrameworkCore.DbContext

# Types whose name matches one of these patterns (glob, * wildcard, case-insensitive) are not checked.
# Default: *Dto, *Request, *Response, *Options, *Settings, *Config, *Configuration, *Constants, *Extensions, *Mapper,
# *Mapping, *Profile, *Validator, *Specification, *Comparer, *Converter
dotnet_diagnostic.DSA043.excluded_type_name_patterns = *Dto, *Options, *Mapper

# Types declared in a namespace that matches one of these patterns are not checked. Default: *.Migrations
dotnet_diagnostic.DSA043.excluded_namespace_patterns = *.Migrations, *.Tests

# Types declared in a file whose name matches one of these patterns are not checked.
# Default: *.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs
dotnet_diagnostic.DSA043.excluded_file_patterns = *.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs
```

### Examples

```ini
# Strict: every class with more than 10 methods and at least 8 branches in a method, whatever it does
dotnet_diagnostic.DSA043.min_cyclomatic_complexity = 0
dotnet_diagnostic.DSA043.min_method_complexity = 8
dotnet_diagnostic.DSA043.min_lines = 0
dotnet_diagnostic.DSA043.min_methods = 10
dotnet_diagnostic.DSA043.require_all_thresholds = true
dotnet_diagnostic.DSA043.require_activity = false

# Lenient: only the very large classes that also handle errors
dotnet_diagnostic.DSA043.min_cyclomatic_complexity = 60
dotnet_diagnostic.DSA043.min_method_complexity = 0
dotnet_diagnostic.DSA043.min_lines = 400
dotnet_diagnostic.DSA043.activity_kinds = catch
```
