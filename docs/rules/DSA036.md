# DSA036

Extract Regex with constant pattern to a static readonly field.

## Rationale

This rule fires when a `Regex` object is created at runtime — either via `new Regex(...)` or via a static `Regex` method (`IsMatch`, `Match`, `Replace`, `Split`, `Matches`) — and all parameters that define the regex (pattern, options, timeout) are compile-time constants or effectively immutable values. The only exception is the **matched input string** (and replacement/evaluator for `Replace`), which is naturally dynamic.

Each `new Regex(pattern)` call allocates a new object and parses the pattern from scratch, constructing an internal finite automaton. When the pattern never changes, this work is redundant and wasteful. The regex should be created once in a `private static readonly` field and reused across all invocations.

Static `Regex` methods (`Regex.IsMatch(input, pattern)`, etc.) internally create and cache `Regex` instances, but the cache is bounded (15 entries by default). In high-throughput code with many distinct patterns, cache evictions cause repeated parsing. Pre-allocating a static field eliminates cache pressure entirely.

### Performance impact

- **`new Regex(pattern)`**: allocates a new object and parses the pattern on every call. In a loop of N iterations, this is O(N × P) where P is the pattern parsing cost.
- **`Regex.IsMatch(input, pattern)`**: uses an internal LRU cache of 15 entries. If the cache is full, the least-recently-used pattern is evicted and must be re-parsed on the next call.
- **Static readonly field**: pattern is parsed once at class initialization. All subsequent uses are O(1) field access.

### CWE-400 / CWE-405 Mitigation

In the context of cybersecurity, unbounded `Regex` allocations inside a tight loop or request-processing pipeline can be exploited for denial-of-service. An attacker who can trigger the code path repeatedly forces the server to waste CPU cycles on redundant pattern parsing and increases GC pressure.

### IEC 62443 Certification: Resource Availability

In the context of **IEC 62443 certification**, this supports **FR 7 (Resource Availability)** by ensuring that computational resources are not wasted on redundant object construction.

## What counts as "effectively constant"

An argument is considered effectively constant if it is:

- A **string literal** (e.g., `@"\d+"`)
- A **const** field or local variable
- A **static readonly** field
- An **enum literal or combination** (e.g., `RegexOptions.IgnoreCase | RegexOptions.Compiled`)
- A **local variable** initialized from any of the above and **never reassigned** in the enclosing scope

An argument is **NOT** considered constant if it is:

- A method parameter
- A method/property call result (including `TimeSpan.FromSeconds(...)` — extract to a `static readonly` field instead)
- An instance field (even `readonly` — the value varies per instance)
- A variable that is reassigned, passed by `ref`, or passed by `out`

## Code sample

```csharp
public class DataProcessor
{
    public bool ValidateCode_NotOk(string input)
    {
        // DSA036 fires: pattern is a constant string literal
        var regex = new Regex(@"\d{3}-\d{4}", RegexOptions.Compiled);
        return regex.IsMatch(input);
    }

    public string SanitizeText_NotOk(string input)
    {
        // DSA036 fires: static Regex method with constant pattern
        return Regex.Replace(input, @"\s+", " ");
    }

    // Fixed: hoisted to static readonly fields
    private static readonly Regex _codeRegex = new Regex(@"\d{3}-\d{4}", RegexOptions.Compiled);
    private static readonly Regex _whitespaceRegex = new Regex(@"\s+");

    public bool ValidateCode_Ok(string input)
    {
        return _codeRegex.IsMatch(input);
    }

    public string SanitizeText_Ok(string input)
    {
        return _whitespaceRegex.Replace(input, " ");
    }
}
```

## Matched patterns (code is NOT OK)

```cs
// new Regex with literal pattern:
var regex = new Regex(@"\d+");

// new Regex with literal pattern and options:
var regex = new Regex(@"\d+", RegexOptions.Compiled | RegexOptions.IgnoreCase);

// new Regex with const variable:
const string pattern = @"\d+";
var regex = new Regex(pattern);

// new Regex with non-mutated local variable:
var pattern = @"\d+";
var regex = new Regex(pattern);  // pattern is never reassigned

// Static Regex methods with constant pattern:
Regex.IsMatch(input, @"\d+");
Regex.Match(input, @"\d+");
Regex.Replace(input, @"\d+", "X");
Regex.Split(input, @"\s+");
Regex.Matches(input, @"\d+");
```

## Not matched patterns (code is OK)

```cs
// Already in a static readonly field:
private static readonly Regex _regex = new Regex(@"\d+");

// Pattern comes from a method parameter:
public bool Check(string input, string pattern) => new Regex(pattern).IsMatch(input);

// Pattern comes from a method call result:
var regex = new Regex(GetPattern());

// Pattern local variable is reassigned:
var pattern = @"\d+";
if (strict) pattern = @"^\d+$";
var regex = new Regex(pattern);

// Options come from a parameter:
public bool Check(string input, RegexOptions opts) => new Regex(@"\d+", opts).IsMatch(input);
```

## Included Code Fixer and Mitigation

The code fix extracts the `Regex` creation to a `private static readonly` field at the class level.

**For `new Regex(...)` constructor calls:**
```cs
// Before:
public class Validator
{
    public bool Check(string input)
    {
        var regex = new Regex(@"\d+", RegexOptions.Compiled);
        return regex.IsMatch(input);
    }
}

// After:
public class Validator
{
    private static readonly Regex _regex = new Regex(@"\d+", RegexOptions.Compiled);
    public bool Check(string input)
    {
        var regex = _regex;
        return regex.IsMatch(input);
    }
}
```

**For static `Regex` method calls:**
```cs
// Before:
return Regex.IsMatch(input, @"\d+", RegexOptions.IgnoreCase);

// After:
private static readonly Regex _regex = new Regex(@"\d+", RegexOptions.IgnoreCase);
// ...
return _regex.IsMatch(input);
```
