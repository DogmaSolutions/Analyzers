# DSA053

`Count` (or `CountAsync`) whose number is only compared with zero: ask the real question with `Any`.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA053                                                                                        |
| Title        | Use Any instead of Count when the number is only compared with zero                           |
| Category     | Performance                                                                                   |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ✅                                                                                             |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

```csharp
var orders = await _db.Orders.CountAsync(o => o.CustomerId == id, ct);   // DSA053
if (orders > 0)
{
    return Conflict("The customer has orders");
}
```

The number is never used: the code wants to know **whether** there are orders, and asks **how many**. Counting has a cost that grows with the number of matches, and existence does not:

| | `Count(...)` | `Any(...)` |
|:--|:--|:--|
| Database | `SELECT COUNT(*) FROM [Orders] WHERE ...`: scans **every** match | `SELECT CASE WHEN EXISTS (SELECT 1 ...)`: **stops at the first** |
| Deferred sequence in memory | evaluates **every** element, re-running whatever the sequence does while it is enumerated | stops at the first element |
| Determinism | a sequence that changes, or has side effects when enumerated, can give a different number at each enumeration | the question *"is there one?"* does not depend on how many |

The rule reports:

* the number kept in a **local variable** that is only ever compared with zero (`> 0`, `!= 0`, `>= 1`, `== 0`, `< 1`, `<= 0`, also `0 < n` and the patterns `n is > 0`, `n is 0`, `n is not 0`...):

```csharp
var count = items.Count(i => i.IsActive);   // DSA053
if (count == 0) { ... }
```

* `CountAsync` / `LongCountAsync` **with a predicate** compared with zero right away (`await q.CountAsync(p) > 0`), which CA1828 does not report.

The methods are `Count`, `LongCount`, `CountAsync` and `LongCountAsync`. The async versions are reported only when the provider has the matching `AnyAsync` (Entity Framework Core has it).

### What is *not* reported

**When the number is used**: the rule is silent as soon as the number is **returned**, **assigned** (variable, field, property, tuple...), **passed** (a log, an argument), **captured** by a lambda, **reassigned**, used in an **expression** (`n * 2`), or compared with anything else than zero: `n > 1`, `n == 1`, `n >= 2` and `n > id` are not existence tests.

**When `Length` and `Count` are the right tool.** Some sequences know their size without enumerating anything, and for them the property is O(1) and perfectly legitimate, and `Any()` is no better (it is even worse, see CA1860):

| Type | Why it is fine |
|:-----|:---------------|
| Arrays (`Length`) | the size is stored |
| `string` (`Length`) | the size is stored |
| `List<T>`, `ICollection<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, `HashSet<T>`, `Dictionary<,>`... (`Count`) | the size is stored |

The rule does not report these (`report_types_with_cheap_count` turns them on). It reports an `IEnumerable<T>`, even if it is a list at run time, because the code cannot rely on it: the same code works with any sequence, and a sequence that has to be enumerated is where the cost and the non-determinism are. `Length` and `Count` *properties* are never reported at all.

### What CA1827 and CA1828 report already

The comparisons made right away on the call (`q.Count() > 0`, `q.Count(p) == 0`, `await q.CountAsync() > 0`) are already reported by the .NET analyzers (**CA1827** for `Count()` and `LongCount()`, **CA1828** for `CountAsync()` and `LongCountAsync()` without a predicate). To avoid reporting the same line twice they are left to them. What those analyzers miss, and this rule reports:

* the number **kept in a variable** (`var n = q.Count(); if (n > 0)`), for both sync and async;
* **`CountAsync` / `LongCountAsync` with a predicate** compared right away.

`report_direct_comparisons = true` reports all the direct comparisons, for the projects that disabled CA1827 and CA1828.

## 🔐 Security implications

Counting every match to answer a yes/no question amplifies the work of the data source with the size of the data, and an endpoint that does it on user-controlled input is a cheap target for resource exhaustion.

* **CWE-1049** — [Excessive Data Query Operations in a Large Data Table](https://cwe.mitre.org/data/definitions/1049.html)
* **CWE-405** — [Asymmetric Resource Consumption (Amplification)](https://cwe.mitre.org/data/definitions/405.html)

## 🔦 Code sample

```csharp
public class Samples
{
    public void NotOk()
    {
        // this WILL trigger the rule: the number is only compared with zero
        var orders = db.Orders.Count(o => o.CustomerId == id);
        if (orders > 0) { ... }
    }

    public void Ok()
    {
        // this WILL NOT trigger the rule: the number is used
        var count = db.Orders.Count(o => o.CustomerId == id);
        logger.LogInformation("{Count} orders", count);
        return count > 0;
    }
}
```

## ℹ️  Matched patterns (code is NOT OK)

```cs
// this WILL trigger the rule: the number is only compared with zero
var orders = db.Orders.Count(o => o.CustomerId == id);
if (orders > 0) { ... }

// this WILL trigger the rule: CountAsync with a predicate, which CA1828 does not report
if (await db.Orders.CountAsync(o => o.CustomerId == id, ct) == 0) { ... }
```

## ✅ Not matched patterns (code is OK)

```cs
// this WILL NOT trigger the rule: the number is used
var count = db.Orders.Count(o => o.CustomerId == id);
logger.LogInformation("{Count} orders", count);
return count > 0;

// this WILL NOT trigger the rule: not an existence test
if (db.Orders.Count(o => o.CustomerId == id) > 1) { ... }

// this WILL NOT trigger the rule: the size is known, Length and Count are the right tool
if (array.Length > 0) { ... }
if (list.Count == 0) { ... }
var n = list.Count(); if (n > 0) { ... }
```

## 🛠️ Included Code Fixer and Mitigation

*Use 'Any' instead of 'Count'* rewrites the test: the call keeps its predicate, type arguments and `CancellationToken`; the comparison becomes the call (negated when it tests for absence).

```csharp
// before
var count = await _db.Orders.CountAsync(o => o.CustomerId == id, ct);
if (count == 0) { ... }
// after
var hasItems = await _db.Orders.AnyAsync(o => o.CustomerId == id, ct);
if (!hasItems) { ... }
```

The variable becomes a `bool` named `hasItems` (a name already used in the member gets a number), and every test of the variable is rewritten. *Fix all* rewrites all the tests of a document in one pass. The review comment is always offered.

The *Add comment for code review* action is always offered.

## ⚙️ Rule configuration

### Severity

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA053: Use Any instead of Count when the number is only compared with zero
# Possible values: error, warning, suggestion, silent, none
dotnet_diagnostic.DSA053.severity = warning
```

Every option below is optional. A missing, blank or malformed value is ignored and the default is used. Lists are comma-separated; a list **replaces** the default list.
