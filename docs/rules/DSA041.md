# DSA041

A `switch` (statement or expression) whose governing value is of an enum type that declares more than `max_enum_members` members (default 4). Beyond a handful of cases a switch stops being the right tool: the decisional complexity invites always-incorrect control flow, business-logic errors and missing-default defects. The remedy is usually the Strategy pattern.

## 💡 Rationale

A `switch` (statement or expression) driven by an enum with many members has grown past the point where a switch is the right tool. As the number of cases rises, the decisional complexity concentrated in one place becomes hard to keep correct and exhaustive, which invites:

* **CWE-670** — [Always-Incorrect Control Flow Implementation](https://cwe.mitre.org/data/definitions/670.html)
* **CWE-840** — [Business Logic Errors](https://cwe.mitre.org/data/definitions/840.html)
* **CWE-478** — [Missing Default Case / non-exhaustive expression](https://cwe.mitre.org/data/definitions/478.html)

```csharp
public enum Color { Red, Green, Blue, Yellow, Orange } // 5 members

// SMELL: a growing switch over a growing enum.
int Rank(Color c)
{
    switch (c)   // DSA041
    {
        case Color.Red: return 1;
        case Color.Green: return 2;
        case Color.Blue: return 3;
        case Color.Yellow: return 4;
        default: return 0;
    }
}
```

The analyzer counts the enum's declared members (unwrapping `Nullable<TEnum>`) and fires when that count exceeds the configured threshold. The threshold is configurable via `dotnet_diagnostic.DSA041.max_enum_members` (default 4).

## 🔦 Code sample

```csharp
public enum Color { Red, Green, Blue, Yellow, Orange } // 5 members (> default 4)

public class Ranking
{
    public int Rank_NotOk(Color c)
    {
        // this WILL trigger the rule: switch over an enum with more than 4 members
        return c switch
        {
            Color.Red => 1,
            Color.Green => 2,
            Color.Blue => 3,
            Color.Yellow => 4,
            Color.Orange => 5,
            _ => 0
        };
    }

    // this WILL NOT trigger the rule: dispatch through a strategy map
    private static readonly Dictionary<Color, int> _ranks = new()
    {
        [Color.Red] = 1, [Color.Green] = 2, [Color.Blue] = 3, [Color.Yellow] = 4, [Color.Orange] = 5
    };

    public int Rank_Ok(Color c) => _ranks.TryGetValue(c, out var rank) ? rank : 0;
}
```

## ℹ️  Matched patterns (code is NOT OK)

```cs
// Switch STATEMENT over an enum with more than max_enum_members members:
switch (color) { case Color.Red: ...; case Color.Green: ...; /* > 4 members total */ }

// Switch EXPRESSION over the same enum:
var rank = color switch { Color.Red => 1, Color.Green => 2, /* ... */ };

// Nullable enum is unwrapped and still counted:
switch (nullableColor) { /* Color has > 4 members */ }
```

## ✅ Not matched patterns (code is OK)

```cs
// Enum with at most max_enum_members members (default 4):
enum Suit { Hearts, Diamonds, Clubs, Spades }
switch (suit) { case Suit.Hearts: ...; /* 4 members — OK */ }

// Switching over a non-enum governing value:
switch (statusCode) { case 200: ...; case 404: ...; }
```

## 👉️ Rules of thumb for prevention and proactive posture

- When the decisional complexity keeps growing, the right tool is usually the **[Strategy pattern](https://en.wikipedia.org/wiki/Strategy_pattern)**: give each enum value (or the behaviour it selects) its own strategy object and dispatch through a map, so each case lives in its own testable unit instead of one large switch.
- Keep the enum small and cohesive; a large enum driving a large switch is often a sign that the enum is modelling several distinct concerns.

### Switch-based (flagged) vs. Strategy pattern (preferred)

The switch below is driven by a five-member enum (more than the default `max_enum_members` of 4), so `DSA041` reports it. Every new shipping method forces an edit to this one method, and each branch is only reachable through it:

```csharp
public enum ShippingMethod { Standard, Express, Overnight, Freight, International }

public sealed class ShippingCostCalculator
{
    public decimal GetCost(ShippingMethod method, decimal weight) =>
        switch (method) // ⚠ DSA041: switch driven by a 5-member enum
        {
            ShippingMethod.Standard      => weight * 1.0m,
            ShippingMethod.Express       => weight * 2.5m,
            ShippingMethod.Overnight     => weight * 4.0m,
            ShippingMethod.Freight       => weight * 0.5m + 50m,
            ShippingMethod.International  => weight * 3.0m + 20m,
            _ => throw new ArgumentOutOfRangeException(nameof(method)),
        };
}
```

The equivalent logic as the Strategy pattern: each case becomes its own small, independently testable type, and dispatch is a dictionary lookup. Adding a method means adding a strategy and one map entry — the calculator itself no longer changes:

```csharp
public interface IShippingCostStrategy
{
    decimal Calculate(decimal weight);
}

public sealed class StandardShipping : IShippingCostStrategy
{
    public decimal Calculate(decimal weight) => weight * 1.0m;
}

public sealed class ExpressShipping : IShippingCostStrategy
{
    public decimal Calculate(decimal weight) => weight * 2.5m;
}

public sealed class OvernightShipping : IShippingCostStrategy
{
    public decimal Calculate(decimal weight) => weight * 4.0m;
}

public sealed class FreightShipping : IShippingCostStrategy
{
    public decimal Calculate(decimal weight) => weight * 0.5m + 50m;
}

public sealed class InternationalShipping : IShippingCostStrategy
{
    public decimal Calculate(decimal weight) => weight * 3.0m + 20m;
}

public sealed class ShippingCostCalculator
{
    private static readonly IReadOnlyDictionary<ShippingMethod, IShippingCostStrategy> Strategies =
        new Dictionary<ShippingMethod, IShippingCostStrategy>
        {
            [ShippingMethod.Standard]      = new StandardShipping(),
            [ShippingMethod.Express]       = new ExpressShipping(),
            [ShippingMethod.Overnight]     = new OvernightShipping(),
            [ShippingMethod.Freight]       = new FreightShipping(),
            [ShippingMethod.International]  = new InternationalShipping(),
        };

    public decimal GetCost(ShippingMethod method, decimal weight) =>
        Strategies.TryGetValue(method, out var strategy)
            ? strategy.Calculate(weight)
            : throw new ArgumentOutOfRangeException(nameof(method));
}
```

In a DI-based application the map is usually replaced by keyed service resolution (or an injected `IEnumerable<IShippingCostStrategy>` where each strategy advertises the method it handles), removing the hand-maintained dictionary entirely.

## ⚙️ Rule configuration

The threshold `max_enum_members` is configurable via `.editorconfig`; the default is **4** (the rule fires when the enum declares **more than** that many members):

```ini
[*.cs]
dotnet_diagnostic.DSA041.max_enum_members = 4
```

In order to change the severity level of this rule, change/add this line in the `.editorconfig` file:

```ini
# DSA041: Avoid switching over an enum with many members
dotnet_diagnostic.DSA041.severity = error
```
