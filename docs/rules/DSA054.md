# DSA054

A private field that is assigned and then read only inside the same member holds no state.

| Property     | Value                                                                                          |
|:-------------|:-----------------------------------------------------------------------------------------------|
| Rule ID      | DSA054                                                                                        |
| Title        | A private field that is assigned and then read only inside the same member holds no state     |
| Category     | Code Smell                                                                                    |
| Severity     | ⚠ Warning                                                                                     |
| Refactoring available | ✅ (`??=`, only when it is safe)                                                       |
| Code-review tools available | ✅                                                                                             |
| Is enabled   | ✅                                                                                             |

## 💡 Rationale

A field exists to keep a value **from one call to the next**. A field whose every use is inside one member, and whose every read comes after an assignment that always runs, keeps nothing: each call overwrites it before reading it.

```csharp
private string? _label;

public string Label
{
    get
    {
        _label = BuildLabel();      // (DSA054) overwritten on every call...
        return _label;              // ...and read right after: the field is not a cache
    }
}
```

There are two possible intents, and the code implements neither of them:

| Intent | What the code should be |
|:-------|:------------------------|
| **Memoization**: compute once, reuse | Assign only when the value is not computed yet: `_label ??= BuildLabel();` |
| **A local variable** that was declared as a field | Declare it in the member, and delete the field |

The first one is a **performance** defect that no compiler, no IDE and no other analyzer reports: the code compiles, runs, and returns the right value, and the computation (a query, a parse, a reflection call) runs on every access. The second one is a **robustness** defect: as a field, two threads running the member at the same time overwrite each other's value.

Neither `CS0414`, `IDE0052` (a private field that is never read), `IDE0059` (a local that is assigned and not used) nor `DSA007` (lazy initialization with a null check) reports it: the field *is* read, and the code has no null check at all.

## ✅ What is reported

A **private** field, not `readonly`, not `const`, not `volatile`, without attributes, such that:

1. **Every use** of the field (reads and writes) is inside **one single member**: a method, a constructor, an accessor, an operator, an expression-bodied member.
2. An **assignment** (`f = ...;`, `this.f = ...;`, `return f = ...;`, or an expression body `=> f = ...`) is a statement of the body (or of a plain nested block or `lock`) that comes **before every other use** of the field, so that it always runs before any read.
3. After that assignment the field is only read or reassigned directly (a plain use, `f++`, `f += 1`).

| Scenario | Shape | Message |
|:---------|:------|:--------|
| **Missing memoization** | The member returns the field (or the assignment itself): `_v = Compute(); return _v;`, `return _v = Compute();`, `=> _v = Compute()` | The value is recomputed on every call: use `??=` (reference type or `Nullable<T>`), a flag for any other type, `Lazy<T>` or a lock when the computation must run once. Or make it a local |
| **Leftover field** | The member uses the field for something else: `_t = a + b; return _t * 2;` | It is a local that was declared as a field: make it local. Or, if you meant to keep it, memoize |
| **Never read** (optional, `report_never_read`) | The field is assigned and never read anywhere | Delete it, or read the value |

The diagnostic is located on the **assignment**, and the message names the field and the member.

## 🚫 What is *not* reported

The rule only reports what it can **prove**. Whenever the code could be using the field as real state, it stays quiet:

| Case | Why |
|:-----|:----|
| The field is used by **more than one member** (read in another member, assigned in the constructor and again in a method...) | It carries a value between members |
| A read **before** the assignment (`if (_v == null) _v = ...;`, `var old = _v; _v = ...;`, `_v = _v + 1;`, `_v++;` first) | The value of a previous call is used: it is state, or a lazy initialization ([DSA007](DSA007.md)) |
| `_v ??= Compute();` | It is already a memoization |
| A **conditional** assignment (`if`, loop, `try`, `switch`, `?:`, a nested expression) | Some paths read the previous value |
| A use inside a **lambda, anonymous method, local function or query** | It can run later, after the field was overwritten by another call |
| `ref`, `out`, `in`, `&` | The field can be changed through the alias |
| **Another instance** (`other._v`, `other?._v`, `new C { _v = ... }`), deconstruction targets (`(_a, _b) = ...`) | Not a plain variable of the member |
| A member that **calls itself** | The inner call sees the outer assignment: the field is shared by the calls |
| `readonly`, `const`, `volatile`, `[ThreadStatic]`, any attribute (serialization, injection, ...), pointers, fixed buffers, auto-property and event backing fields | Not plain fields, or the attribute gives them a meaning the rule cannot see |
| `public`, `protected`, `internal` fields | Other code can use them |
| Generated files | `*.Designer.cs`, `*.g.cs`... are ignored |

## 🔧 Code fix

* **Memoize the value with `??=`**: replaces `=` with `??=`. It is offered **only when nothing else has to change**: the field is a reference type or a `Nullable<T>` (`??=` needs a value that can be null, and null means "not computed yet"), the assignment is the first statement of the member and the only write, the member is not a constructor or a finalizer, and the language version is C# 8 or later. Any other case (a `int`, a `bool`, a computation that must run once) needs a design decision and gets only the review comment.
* **Add comment for code review**: inserts a comment that references the rule.

> **Memoization is not free of traps.** `_v ??= Compute()` is **not thread-safe**: two threads can both see `null`, both compute, and both assign (the last one wins, and the computation runs more than once). If the computation has side effects, is expensive, or must produce one single instance, use `Lazy<T>` (`LazyThreadSafetyMode.ExecutionAndPublication`) or a `lock` (see [DSA007](DSA007.md)). A `ref`-type result must also be safe to share between callers, and the cached value is never refreshed: if the source can change, the cache is wrong.

## ⚙ Options

All options are set in the `.editorconfig`, under `dotnet_diagnostic.DSA054.<key>`.

| Key | Default | Meaning |
|:----|:--------|:--------|
| `severity` | `warning` | The severity of the rule |
| `report_never_read` | `false` | Also report the fields that are assigned and never read anywhere (the compiler and the IDE already report most of them) |
| `report_static_fields` | `true` | Report the `static` fields too |
| `excluded_type_name_patterns` | *(empty)* | Glob patterns of the type names to ignore |
| `excluded_namespace_patterns` | *(empty)* | Glob patterns of the namespaces to ignore |
| `excluded_base_types` | *(empty)* | Types whose descendants are ignored |
| `excluded_field_name_patterns` | *(empty)* | Glob patterns of the field names to ignore |
| `excluded_member_name_patterns` | *(empty)* | Glob patterns of the member names to ignore (`Name`, `Property.get`, `operator +`) |
| `excluded_file_patterns` | `*.Designer.cs, *.generated.cs, *.g.cs, *.g.i.cs` | Glob patterns of the files to ignore |

```ini
[*.cs]
dotnet_diagnostic.DSA054.severity = warning
dotnet_diagnostic.DSA054.report_never_read = true
dotnet_diagnostic.DSA054.excluded_member_name_patterns = Render*
```
